# pxd — 온보딩 설문 답변 저장 (API 방식)

pxd 신입 온보딩 설문의 답변을 **Vercel API** 로 전송합니다.
누구 기기에서든 저장 즉시 전체 참여자에게 실시간 공유됩니다 (별도 auth 불필요).

- **엔드포인트**: `https://pxd-api.vercel.app/api/responses`
- **저장소**: Upstash Redis (Vercel Marketplace)

## 입력

`$ARGUMENTS` — 다음 6개 항목이 포함된 답변 텍스트 (자유 형식):
1. 이름
2. 나이
3. 취미
4. 좋아하는 음식
5. 좋아하는 영화
6. MBTI

## 실행 단계

### 1. 답변 파싱

`$ARGUMENTS` 에서 6개 필드를 추출:
- "이름 홍길동, 나이 32" 같은 명시적 형식도 지원
- "저는 홍길동이고 32살입니다" 같은 자연 문장도 지원

### 2. 누락 필드 확인 (필수 6개 모두 있어야 저장 가능)

6개 필드 (**이름 · 나이 · 취미 · 좋아하는 음식 · 좋아하는 영화 · MBTI**) 중 **하나라도 비어있으면 저장을 진행하지 말 것**.

대신 다음처럼 **자연스럽게 다시 물어봄**:

- 하나 누락된 경우:
  > "김영희씨, 좋아하는 음식이 빠졌어요. 어떤 거 좋아하세요?"
- 여러 개 누락된 경우:
  > "김영희씨, 아직 안 알려주신 게 있어요: 좋아하는 음식, MBTI. 알려주시면 저장할게요."

사용자가 후속 답변을 주면 그 정보만 합쳐서 다시 파싱하고, **6개 다 채워졌을 때만** 다음 단계로.

이 단계는 서버 검증 (API 층에서도 400 을 던짐) 과 함께 **이중 방어선**을 이룸. 하네스 층은 UX 를 위한 부드러운 대화, API 층은 무결성 보장.

### 3. API 로 전송

JSON 페이로드로 POST:

```bash
curl -sS -X POST https://pxd-api.vercel.app/api/responses \
  -H "Content-Type: application/json" \
  -d '{
    "name": "<이름>",
    "age": "<나이>",
    "hobby": "<취미>",
    "food": "<음식>",
    "movie": "<영화>",
    "mbti": "<mbti>",
    "raw": "<$ARGUMENTS 원문>"
  }'
```

응답: `{ "ok": true, "saved": {...}, "count": N }`

### 4. 로컬 백업 (선택)

- 폴더: `~/pxd-responses/`
- 폴더 없으면 만들고, `<이름>.md` 로 파일 저장
- 목적: 네트워크 실패 시 사용자 답변이 사라지지 않게

## 보고 형식

```
✓ 온보딩 응답 저장 완료
- 이름: <이름>
- API 저장: ✓ (총 응답 N개)
- 로컬 백업: ✓ ~/pxd-responses/<이름>.md
```

API 실패 시:
```
⚠ API 저장 실패 (네트워크 문제일 수 있음)
- 로컬 백업: ✓ ~/pxd-responses/<이름>.md
- 나중에 재시도: /pxd 를 다시 실행하면 됩니다
```

## 특이 케이스

- **인자 비어있음**: pxd 온보딩 설문 6개 필드를 안내하고 종료.
- **6개 중 하나라도 누락**: 저장하지 말고 위 "누락 필드 확인" 절차대로 사용자에게 다시 물음.
- **MBTI 형식 이상**: 4글자 알파벳(예: INTJ)이 아니면 확인.
- **API 400 (`required_fields_missing`)**: 이론상 하네스에서 미리 걸러야 함. 그럼에도 발생하면 서버 응답의 `missing` 배열을 사용자에게 그대로 보여주고 다시 요청.
- **API 500 에러**: 로컬 백업만 저장하고 재시도 안내.
